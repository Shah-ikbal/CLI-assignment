COMMAND 3: ls -la /dev/fd/ (File descriptor directory)
----------------------------------------------------------------
$ ls -la /dev/fd/
total 26
dr-xr-xr-x  1 root  wheel     0  /dev/fd/.
srw-rw-rw-  0 user  staff     0  /dev/fd/0   (stdin)
--w-------  1 user  staff  1307  /dev/fd/1   (stdout)
--w-------  1 user  staff  1307  /dev/fd/2   (stderr)
s-w--w--w-  0 user  staff     0  /dev/fd/3
srw-rw-rw-  0 user  staff     0  /dev/fd/4

EXPLANATION:
/dev/fd/ is a virtual directory where each entry corresponds to an
open file descriptor in the current process. FD 0 is a socket (stdin),
FD 1 and 2 are write-only pipes (stdout/stderr). This confirms Linux
treats everything as a file, including I/O streams.

----------------------------------------------------------------
COMMAND 4: Output redirection (stdout and stderr separately)
----------------------------------------------------------------
$ echo "stdout message" > stdout.txt 2> stderr.txt
$ echo "error message" >&2 2>> stderr.txt

stdout.txt contents:
  stdout message
  combined test

stderr.txt contents:
  error message

EXPLANATION:
The > operator redirects stdout to a file (overwriting), while 2>
redirects stderr separately. This allows applications to log normal
output and errors to different files, which is essential for debugging
logging issues in production systems.

----------------------------------------------------------------
COMMAND 5: Redirect stdout and stderr to separate files
----------------------------------------------------------------
$ (echo "normal output"; echo "error output" >&2) > combined_out.txt 2> combined_err.txt

combined_out.txt: normal output
combined_err.txt: error output

EXPLANATION:
By grouping commands and redirecting both streams independently,
we can capture standard output and error output into separate files
simultaneously, mimicking how logging frameworks separate log levels.

----------------------------------------------------------------
HOW LINUX MANAGES FILE I/O
----------------------------------------------------------------
1. Everything-is-a-file model: Regular files, directories, devices,
   sockets, and pipes are all accessed through file descriptors (FDs).
2. Standard streams: FD 0 (stdin), FD 1 (stdout), FD 2 (stderr) are
   inherited by every process and can be redirected with >, >>, 2>, &>.
3. Kernel buffer cache: Read/write operations go through the kernel's
   page cache for performance; data is flushed to disk asynchronously.
4. Open file table: The kernel maintains a per-process table of open
   FDs; lsof and /proc/<pid>/fd expose this on Linux systems.
5. Resource limits: ulimit prevents runaway processes from exhausting
   system resources like file descriptors, memory, or CPU time.
6. Redirection at shell level: The shell sets up FD duplication before
   exec-ing a program, so applications write to files without code changes.
