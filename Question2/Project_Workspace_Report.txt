EXPLANATION:

----------------------------------------------------------------
COMMAND 4: Apply secure permissions
----------------------------------------------------------------
$ chmod 700 secure_project
$ chmod 750 secure_project/docs secure_project/src
$ chmod 640 secure_project/docs/readme.txt secure_project/config/settings.conf
$ chmod 750 secure_project/config secure_project/backups
$ chmod 750 secure_project/src/app.sh

EXPLANATION:
Permissions were tightened using chmod. The root directory is now
700 (owner-only access). Subdirectories are 750 (owner full, group
read/execute). Sensitive files are 640 (owner read/write, group
read only). The executable script app.sh is 750.

COMMAND 7: umask
----------------------------------------------------------------
$ umask
022

EXPLANATION:
The umask value 022 means new files are created without write
permission for group and others (default file: 644, directory: 755).
We explicitly used chmod because umask alone does not produce the
stricter 700/750/640 permissions required for this secure workspace.

----------------------------------------------------------------
HOW PERMISSIONS PROTECT PROJECT DATA
----------------------------------------------------------------
1. Directory 700 on secure_project: Only the owner can enter the
   workspace at all — outsiders cannot even list its contents.
2. Directory 750 on subdirs: Group members can browse but not modify
   structure; others are completely blocked.
3. File 640 on docs/config: Confidential files are readable only
   by owner and group, never by other system users.
4. File 750 on app.sh: Only owner can write; group can execute but
   not modify the script, preventing unauthorized code changes.
5. Principle of least privilege: Each resource has the minimum
   permissions needed, reducing attack surface and data leakage risk.
